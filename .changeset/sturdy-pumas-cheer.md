**`progress.percent` now moves as plans complete inside the current phase, instead of freezing at the completed-phase floor for the phase's whole duration** — the milestone percent is composed per phase (a closed phase fills its slot, an open phase fills it by its own summarized/plans fraction, an open phase with no plan files fills nothing) instead of capping the whole milestone by the completed-phase count with `min(plan_fraction, phase_fraction)`. Under the cap, the bar sat at a constant for the whole of every phase once its plan fraction overtook the phase count — `percent: 67` beside `completed_plans: 39, total_plans: 39`. Adding plans to an in-flight phase no longer drags the whole milestone down with the global plan fraction; the effect is now **bounded to that phase's own slot** (a 2-phase milestone with one verified phase and one open at 1/2 reads 75, and 67 once that open phase gains a third plan) rather than eliminated. The no-false-100% guarantee the cap served is kept: unrealized future phases still contribute nothing (they carry no passing `*-VERIFICATION.md`, so they are never counted complete), and the composed value for a milestone with any phase still open is held at 99. `state json`, `state sync`, `state update-progress` and the STATE.md body bar all apply the same composition to the phase set each is given. The `progress-ratchet` merge that runs on every resyncing state write (#4129) no longer recomputes `percent` from the four aggregate counters when the merge overrode none of them — that recompute would otherwise discard the composed value and write the old `min()` result back, reverting the bar on the next state write. (Two limits are pre-existing and untouched here, both instances of the same `state-transition.cts` sample-threading boundary #3634 already names: a path that recomputes percent from aggregates alone — the ratchet's override branch among them — is not bound by the 99 ceiling and does not see per-phase composition; and `buildStateFrontmatter` de-duplicates directories that normalize to the same phase number per #2445/#3355 while `cmdStateSync` does not, an asymmetry that reproduces on the base commit.)
